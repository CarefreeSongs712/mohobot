# 市场运行时事务恢复：最小修复设计

日期：2026-11-24。状态：对话设计与本规格文件均经用户批准，进入实施与验证。
范围：隔离工作树中的市场事务实现，不推送、不部署，不接触业务数据；保留已有改动。未授权提交，故本文暂不提交。

## 背景与目标

静态审查和临时合成插件实验确认三个 P2 可用性问题：面板卸载绕过运行时事务、旧实例退役失败后恢复记录丢失所有权、日志移入 `.done-*` 后清理重试仍读取旧路径。

成功标准：失败不造成未追踪的旧实例；旧钩子/任务未退出时不移动 live 文件；已提交的新实例不因清理重试被重复加载；无关插件实例保持不变；最终删除失败可同进程恢复。

## 方案选择

1. 推荐：在现有生命周期锁和日志协议上补齐所有权与清理状态，并接通面板调用链。变更小、沿用现有恢复入口。
2. 仅修面板：不足以解决运行时恢复缺陷，不选。
3. 新建持久化状态机或更改日志格式：超出本次需求，不选。

## 架构、组件与数据流

- 面板 DELETE：有市场服务时传 `plugin_system` 给服务卸载；无市场服务时直接调用运行时卸载。均不预先卸载，不全量重载。保留现有响应字段，并可附加运行时 activation/warning。
- 市场服务继续持操作锁，运行时持生命周期锁。路径校验保持不变。
- `_MarketRecovery.previous` 持有旧 meta；在开始退役前设置恢复旧目标的意图。仅退役成功后清空 previous。恢复先完成旧 owner，再处理候选 owner、回滚、恢复旧目标和清理。
- 替换提交并发布后清除“恢复旧目标”标志。清理重试不重启已发布候选。
- `MarketOperation` 记录本对象是否已完成 active → `.done` 重命名。后续 cleanup 只删除 `.done`；不修改操作 ID、回收路径或持久化日志格式。进程重启继续走既有 recover 扫描。

## 错误与兼容性

- 持续关停错误或不退出的取消钩子保留恢复记录并拒绝有冲突的变更，绝不强行卸载资源。
- 瞬态清理失败返回已提交警告，可由现有单插件 reload 或 shutdown 重试。
- 恢复旧插件的激活/收尾若抛错，保留恢复意图以便下次继续，而非清理事务并报告成功。
- shutdown 中终态日志清理若持续失败，记录错误并延后下次启动恢复；在所有者已安全退役后仍完成其余插件 teardown。
- 路由继续使用已有错误映射和审计；404/409/400/500 含义与其他插件写接口保持一致。
- 不保证跨进程并发编辑、断电持久化或插件自行创建的未监管任务安全；沿用现有限制。

## 测试与验收

全部使用临时目录、合成插件和隔离网络运行器：

- 替换和卸载：旧 on_shutdown 抛错、超时且暂不退出时保持 previous 所有权、live/source 未变、无关实例未变；允许关停后重试恢复可 dispatch。
- 替换和卸载：提交后 `.done` 删除一次性失败，reload/shutdown 在同一进程完成清理，不重复激活。
- 回滚期间旧实例重启失败且 shutdown 暂时失败时，下一次恢复重试确实重新尝试旧实例激活。
- 终态 `.done` 清理持续失败时，shutdown 仍运行已加载插件的关闭钩子，且保留待下次重试的日志状态。
- 路由：有/无市场服务，预检失败保留目标实例；成功只改变目标，回收目录和来源记录正确；补实际回收碰撞故障覆盖。
- 日志：终态 cleanup 可重复调用并清除 `.done`，保留来源记录；既有崩溃恢复测试不退化。
- 运行 focused pytest、插件生命周期/热重载、启动关闭冒烟、compileall、Ruff 和 diff 检查。任何失败需查明，未执行项如实报告。
