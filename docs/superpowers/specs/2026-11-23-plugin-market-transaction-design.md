# 插件市场事务与来源一致性设计（#144–#147）

日期：2026-11-23 · 状态：已确认。范围对应 [#144](https://github.com/CarefreeSongs712/mohobot/issues/144)、[#145](https://github.com/CarefreeSongs712/mohobot/issues/145)、[#146](https://github.com/CarefreeSongs712/mohobot/issues/146)、[#147](https://github.com/CarefreeSongs712/mohobot/issues/147)，按工作分工合为一个市场 PR。

## 1. 范围与取舍

- 复用 #149/#130 的插件代次、接纳栅栏、排空/退役与工具暂存，保留 #154 的激活三态、#153 的共享配置存档与显式更新、#150 的包根契约。以 #150 候选 `82f74530` 设计，发布前在实际合入后的 `dev` 上重放。旧进程的准备任务不能跨面板重启修改新代次。
- 已选：崩溃后在下次启动自动恢复；新插件激活失败时，有旧版则回退，没有旧版则保留文件和来源供诊断。禁用按既有启停策略保留，不当作启动失败。
- 仅做进程内串行化及进程非正常退出后的磁盘恢复。不是多进程/共享卷并发写协议，不承诺掉电或文件系统损坏恢复，也不回滚任意插件代码自行产生的数据、网络请求等副作用。不执行真实插件发布、数据迁移或生产操作。
- 不更换 ZIP 安全检查、下载许可规则或索引信任模型，不引入签名、数据库或通用事务框架。直接调用的手工安装器不改变接口；市场使用同一套解压与清单校验原语。面板只改插件、市场、来源段。

## 2. 下载准备与目标提交

1. **准备（不占插件生命周期锁）。** 冻结索引条目及其来源身份，更新时读实际已安装清单和来源记录。缺来源、错来源、同版/旧版或非市场安装的更新在停旧前返回。版本比较以实际已安装清单为准，不信任历史上可能写错的记录版本。下载、实际 SHA256 校验和限额解压到不可发现的同卷暂存目录；要求实际清单 `name`、`author/name`、`version` 与索引一致，并以清单的 `api_version`、`mohobot_version` 检查兼容性。版本、身份、兼容性、缺清单或缺入口文件均在执行插件代码、停旧和写目标前拒绝。保持索引字段的前置兼容性检查。
2. **接纳和复检。** 提交锁序为市场写入锁 → 插件生命周期锁 → 来源记录文件锁。尚未进入提交时，等待锁可取消；同时持有两个协调锁后复检宿主接纳代次、来源身份、名称/命名空间、已安装目录、磁盘版本和来源记录。面板增删来源与这次复检/提交共享市场写入锁，URL 解析和索引网络请求均留在锁外。配置和启停采用进入提交时的最新策略，不用下载前快照。命名空间冲突不执行候选；校验失败不调用任何 `on_shutdown` 或全量重载。插件目录、来源记录与运行时变更只有一个协调入口，面板不再自行拼接 `unload → market → reload`。无市场服务的面板卸载也走同一协议；内置且无外置目录不允许删除。
3. **仅停目标。** 关闭该插件接纳并排空正在派发的回调，完成其任务、钩子和导入退役后，才允许移动旧代码。旧 `on_shutdown` 始终面对旧文件。普通 reload/toggle/config 与提交互斥；提交和回退代次的工具、事件和 tick 在最终状态确定前不发布。未完成退役不是退出；若旧任务超时，保留原文件及 owner，不换目录。若候选超时且仍持资源，不移走它在使用的文件、不发布新旧代次；保留恢复记录，目标标记待收尾。相关 reload/toggle/config、全量重载和后续市场写入不得跨越这条栅栏，后续重试或停机先收尾。其他插件继续按原代次运行。
4. **落盘与激活。** 日志先于文件移动写入。将旧目录移至备份、新目录移进目标；只更新目标的来源记录。按原启停策略加载目标，在源记录、必要的配置写入和提交决定完成后才同步发布可用代次。复用配置有效值规则，候选准备时不覆盖现存配置；如须为不存在的配置写默认归档，该写入也纳入可回退操作。任何补偿都先等正在使用这些目录的任务实际退役。
5. **激活结果。** 启用且启动成功：`active`；配置停用：`disabled`，不执行入口；候选失败且有旧目录（更新）或被遮蔽的内置插件（初装）：恢复旧目录/来源后尝试恢复旧代次。候选失败应明确报错，即便旧版恢复成功；旧版恢复也失败就分别记录，不宣称可用。首次安装无回退对象且失败代次已清理：保留这次文件、来源和运行时错误，返回失败而非安装成功，可手动重载或卸载。手动重载未知名称返回 404，不回退到重启全体。
6. **卸载。** 先停外置目标，保留“代码进回收站”的接口。事务中以同卷移动暂存用户明确选择删除的配置和数据（包括旧数据布局）；提交前任何移动失败都恢复原路径和来源。提交后才清掉被选中的暂存数据，失败则报告待清理，重启仅重试清理该操作持有的暂存对象，不碰后来新生成的同名数据。回收目标冲突或无权限不得覆盖旧回收条目；文件恢复后只尝试恢复该目标，不重载全体。卸载提交后，如有同名内置，只加载内置；显式删除配置时，内置可按 #153 从默认值创建新配置，旧操作清理不得触碰它。如果内置自身激活失败，分别报告“卸载完成”和“内置回退未激活”，不把回退状态冒充运行正常；仍在执行的启动或清理任务按第 3 步保留 owner。

## 3. 取消与启动恢复

- 准备线程即使遇到请求取消，也必须实际退出才释放它使用的归档和暂存目录；未进入提交就不得写 live 路径。提交用单一由应用追踪的工作单元；客户端取消只结束等待意图，不取消提交单元，调用方在锁内等待明确的提交、回退或待恢复结果，再传递取消。停机同样等已接纳的变更结束，或保留 owner/文件并返回未排空，不能靠取消 `to_thread` 的等待者释放所有权。
- 使用市场专用、隐藏且不属于通用过期清理前缀的操作目录，与安装目录同卷。一个持久化记录描述一个正在提交的操作：格式版本、操作 ID/插件名、预期的目录和备份槽、旧/新来源记录、可选的配置/数据移动，以及最后提交决定。来源文件仍保持原来的 JSON 格式；在路径锁内严格读改写，并用同目录临时文件替换，不能用就地截断或把解析失败当空表继续。操作日志也采用写临时文件后替换。移动采用同卷 rename；遇到跨卷路径时拒绝事务，不退化为半完成的复制删除。
- 每个移动以已验证的原路径和事务专属槽为两端；先写意图，按所在槽识别移动未发生/已发生，重复恢复不能删掉已恢复的旧目录。候选被撤下时先移回专属槽，需要它证明恢复位置时不得提早删除。只在目录/记录/运行时的可提交结果确定后写最终决定；回退完成同样先写终态再清理证据。未提交的一律回到操作前的目录和记录；已提交的只完成备份清理或回收，不重复激活。对记录以旧/新值作恢复校验，只还原目标记录并保留其他条目。
- 应用在入口发现和任何插件启动前运行恢复，不依赖网络索引。已拥有候选资源的原进程内重启必须先走退役；新进程没有旧实例，只恢复磁盘，再由冷启动加载。拒绝含路径越界、符号链接接管、未知格式或与操作记录矛盾的状态；保留证据、打印操作 ID 和路径并阻止加载/监听，不猜测、不静默删除。失败的回退以及仍在使用目录的超时代次需可诊断、可重试，不用“报错后释放锁”当作收尾完成。

## 4. 来源身份、缓存与面板

- 来源身份为 `id + 规范化 URL + 代次`。URL 保留有意义的路径、查询和编码，仅规范协议/主机大小写、默认端口等不改变请求资源的部分。自定义源在 URL 改变或删后重建时生成新代次并持久化；同 URL 仅改显示名保留代次；旧记录按稳定兼容身份读取，不用不带身份的旧缓存。官方源使用固定身份。
- 来源列表读与索引首拉分开；先打开来源页再开市场，市场仍会首拉。索引缓存记录身份及最后成功抓取时间，磁盘以 URL 摘要和代次隔离，内存不按裸 ID 复用。并发拉取完成时检验当前身份与刷新顺序，旧代次或被更新的回包不得覆盖当前内存/缓存。代理请求失败再尝试直连；均失败时仅回退同身份的有效缓存。区分 `fresh`、`cached`、`failed` 及尚未尝试的状态，返回最后成功更新时间（从未成功则为空）；面板标明缓存回退或失败，避免把失败的空列表当作成功。
- 市场查询/刷新保留已有字段，增加每源刷新状态。选择条目时冻结来源 URL、代次、下载 URL 和哈希；提交复查身份，把实际安装版本、身份和该快照的来源/下载 URL/哈希写进记录，绝不在下载后用可变 ID 反查。已有 URL 或代次且与当前来源不符时拒绝更新，不自动改绑新源。历史记录若缺少代次，按已有 URL 核对；若还缺 URL，才按旧 ID 兼容。两条兼容路径都须核对已安装清单与归档的插件身份；下一次成功提交补齐身份字段，不批量迁移。
- 安装、更新仍只凭目标结果：保留成功 `activation`（`active` / `disabled`）、`name/path` 和兼容计数，计数不作判定；附目标版本、来源、`loaded/enabled/error`。失败保持字符串 `detail` 便于旧前端显示，并区分未落盘、已安装但激活失败、已回退、待恢复。无效输入/同版更新 400，缺失名称 404，旧来源或已退役请求 409，事务 I/O/恢复失败 500；激活失败返回 400。面板刷新目标列表、给出对应操作提示，审计与实际结果一致；安装失败仍保留可诊断时显示重载/卸载入口。审计写入不决定已落盘事务是否提交。

## 5. 验收与发布

- 先用固定 `dev` 及 #150 候选区分已修复行为与仍能复现的缺陷。用真实 ZIP、文件和 `PluginSystem`/`MarketService`/认证路由，网络只替换索引和传输边界。测试版本/作者/兼容性/缺入口、同版与旧来源、停用、首次失败保留、更新失败回退、内置覆盖失败回退、无关插件的实例/工具/tick 未重启。
- 用事件控制下载取消、连续重复取消、提交线程实际仍活、reload/toggle/config/停机竞争、权限/回收冲突和来源写失败。不使用睡眠推断交错。检查 shutdown 钩子读旧文件，候选未提交不提供工具/派发，停机不丢 owner。
- 用临时目录和子进程直接退出（绕过 `finally`），从记录落盘、每个 rename、来源记录替换、回退中间和提交后清理等断点重启；确认启动先恢复、重复恢复幂等、只更改选中数据，破损日志保留现场并拒绝启动。并列验证未结束任务仅能在原 owner 真退出后恢复；进程退出测试不代表断电测试。
- 用同 URL 与换 URL、删后同 ID 重建、旧请求后完成、缓存损坏/无缓存、来源页先开及代理回退检验索引。真实 Firefox 验收市场安装/更新/回退提示、来源刷新状态、目标列表与审计；扩展原 #154 探针，在有旧版和无旧版两条失败路径分别断言。随后跑隔离 pytest/并发、插件重载与冷启动脚本、Ruff、编译及面板内联 JS 语法检查。
- 依赖 #149/#130 → #154/#153/#150 合入后，重新核对 API/锁序、重放并验收，在 `dev` 开一个独立 PR，不直接推送合入。此规格不代替实现或测试结果。
