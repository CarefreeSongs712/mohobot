# #150 目录插件：按包根定位清单和配置 schema

## 现状与选择

清单解析器已接受相对于包根的 `.py` 路径，安装器与发现逻辑也使用该路径；例如包装过一层目录的 ZIP 含有 `metadata.yaml` 和 `src/worker.py`，可安装到 `data/plugins/{name}/` 并被发现。运行时却从 `worker.py` 的父目录查清单，再用入口 basename 比较清单字段。安装成功后插件误报缺清单，根级 `_conf_schema.json` 也不能与入口一起生效。

继续支持合法的嵌套入口：复用发现阶段传下来的包根，修正加载阶段，而不改扫描与安装约定。不选在清单阶段拒绝所有嵌套入口，因为这会破坏已获接受的包。也不选从入口目录向上猜测清单，因为嵌套目录的同名文件可能遮蔽真正的包根。

## 加载契约

- 对目录插件，`entry_dir` 是包根，`entry_path` 是实际 Python 文件。以包根找 `metadata.yaml`（或已有支持的 `metadata.yml`）与可选 `_conf_schema.json`。即使入口目录下有同名文件，也不使用它们。比较清单 `entry` 与入口相对包根的 POSIX 路径，例如 `src/worker.py`；拒绝不一致。已安装目录名仍须等于清单 `name`，比较对象是包根的 basename，不是 `src`。兼容性和缺清单检查仍在执行入口前。
- 冷启动和单插件重载走同一个加载规则。模块从 `entry_path` 执行，仍以 `mohobot_plugin_<name>` 为模块名；相对导入和旧式绝对导入的搜索根仍为包根，沿用现有导入所有权和卸载。`file` 仍记录相对内置/安装扫描根的路径，例如 `{name}/src/worker.py`。保留无清单的内置 `main.py` 目录插件及直接 `.py` 的行为；单文件不读同级清单，schema 若存在仍按原规则从其父目录读取。
- 同名外置插件继续优先于内置插件，卸载后回退到内置。面板和启动用当前插件的 schema 解释共同存档：#153 提供类型转换、默认值及只保存显式改动。本项不重复实现，也不迁移旧存档；切换来源或查看配置不覆写已有字段。表单主动清空或修改某字段才保存该字段。市场更新事务、已接纳包的安全规则以及嵌套入口目录本身作为 Python 包的语义，均不在本项。

## 验收

1. 用真实 ZIP 安装根目录 `main.py` 和嵌套 `src/worker.py`。嵌套包同时含有效根 schema 和不同的子目录 schema。断言冷启动与单插件重载均执行指定入口、注入根 schema 的默认值且保留原有 `file` 路径；根级相对导入在重载后可用。放错已安装包的目录名时在执行入口前报目录名不一致。
2. 保留内置直接 `.py` 及普通目录入口的正向控制，并运行导入所有权和重载回归。文档说明 `main.py` 是默认值而非唯一入口，schema 总在目录插件的包根。
3. 在带 #153 的离线 ASGI 环境，以旧的逗号字符串存档验证内置 → 同名外置覆盖 → 卸载回退：`GET` 的 schema、类型和默认值切换正确，读取没有改写存档；用显式补丁验证 `POST` 只更改提交字段。市场联网、真实浏览器和生产数据不计入离线验证。
4. 先保留未修代码的失败证据，再跑新增用例、隔离全量和直接热重载/启动检查。当前本地基点为 `b21a37c1fdd2c54bc37df1adf959bd8116b06a01`；等上游依赖合入后重放和复测，再向 `dev` 发独立的 PR。
