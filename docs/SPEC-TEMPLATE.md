### 2.1 本仓库必须核对的边界

不涉及可写"无"，涉及则写明结论：

- **多 Bot**：群内多 Bot 去重、@ 定向、合并回复是否受影响；
- **数据分层**：是否触碰 history（只追加）/ contexts（可写工作记忆）/ SQLite（完成轮次）三者边界；
- **群 gate**：命令、ping、@、引用等触发条件是否变化，`llm_excluded_groups` 与 `external_service_groups` 语义是否保持；
- **权限**：管理员判定、命令折叠、面板/审核面板认证；
- **配置生效方式**：热同步还是重启（容量/信号量类通常需重启）；
- **安全**：是否引入新的外部请求、文件路径、凭据或渲染注入面。

## 3. 模块与架构

### 3.1 模块划分与归属

说明涉及哪些现有模块、新增什么、归属哪一层；遵循 [CODE-MAP](CODE-MAP.md) 的模块边界与 [AGENTS](../AGENTS.md) 的不可变约束。列出不改动的边界，避免范围蔓延。

### 3.2 接口与数据契约

- 输入/输出格式、调用方式、错误码或异常形态；
- 配置项（字段、默认值、热更新还是重启生效）；
- 数据存储变化（是否迁移、是否兼容旧数据、回滚方式）；
- 对外可见行为（命令/接口/面板入口）。

### 3.3 失败与边界

列出可预见的失败、超时、并发冲突与降级路径；说明哪些失败不能静默、哪些必须记录日志。

## 4. 测试与验证

- 新增/修改的测试文件与覆盖的验收标准编号；
- 需要补跑的专项（并发、插件重载、装配冒烟等，见 [DEVELOPMENT §1](DEVELOPMENT.md#1-开发环境与日常循环)）；
- 无法自动化的验证（需真机/外部服务）及未验证范围。

## 5. 非目标

明确本次不做的事，防止实现中扩张范围。

## 6. 未来目标 / 开放问题

可选：后续演进方向、待决策项与依赖。
