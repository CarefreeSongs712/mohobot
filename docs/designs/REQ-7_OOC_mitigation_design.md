# REQ-7 Bot OOC 行为分析与系统性缓解技术方案

> 对应 Issue: [#57](https://github.com/CarefreeSongs712/mohobot/issues/57)
> 对应需求: REQ-7 (Bot OOC 行为分析与缓解方案)

---

## 1. 现象分析与问题归类

在生产聊天与真实用户交互中，Bot 呈现以下五种典型的 OOC (Out Of Character) 或输出失控行为：

### 1.1 内部自查/约束思考泄露（最严重，Issue #57）
- **现象**：Bot 在正式回答前，先输出了一大段“检查系统约束”、“字数检查”、“编写回复”等自查和格式审计文本，甚至直接分段发出 8~9 条消息气泡，最后才发出真正的回复。
- **根因**：
  1. 人设或系统 Prompt 中包含“回复前必须检查约束、控制50字以内、不能用动词括号”等指令。
  2. 部分推理模型或遵循能力较强的模型，将“思考/自查过程”直接作为 output 生成，且没有包裹在 `<think>` / `<thinking>` 标签中。
  3. `mohobot/utils/reply_filter.py` 仅按标签家族（`<think>`、`<tool_call>` 等）剔除内容，对于未包裹标签的纯文本思考过程完全无法识别。
  4. `MessageHandler` 的流式/非流式分段逻辑根据标点和换行将上述自查过程切成了若干气泡直接发送给 QQ 客户端。

### 1.2 未闭合/缺失 `<think>` 标签的思考流泄露
- **现象**：深度思考模型（如 DeepSeek-R1 系列或其他推理增强模型）有时在思考结束时忘记输出 `</think>` 闭合标签，导致后续正文被误吞，或者完全未生成开标签就把推理内容直接输出。

### 1.3 英文单词混杂与语言污染
- **现象**：在中文对话中突兀穿插英文连接词、技术术语或英文代词（如 "Well, 那个...", "As an AI, ...", "Okay so"）。
- **根因**：基础底座模型的语言偏置、Prompt 中未严格限制语言输出空间、温度（temperature）较高导致次优 token 采样。

### 1.4 复读死循环与内容重复
- **现象**：生成长文本时，某句话或某个短语不断重复（如“快坐下歇会儿，累不累，快坐下歇会儿，累不累...”）。
- **根因**：缺乏重复惩罚（frequency_penalty / presence_penalty / repetition_penalty），或者在生成中陷入局部高概率 token 陷阱。

### 1.5 回复过长与过度模板化套话
- **现象**：回复冗长拖沓，带有大量标准 AI 客套话（如“很高兴为您服务”、“希望这个建议对您有所帮助”），破坏人设沉浸感。

## 2. 综合治理与分层防御架构

```
+--------------------------------------------------------------------------+
| 1. Prompt 提示词与人设层 (预防)                                            |
|    - 移除暴露性的“自查”指令，改用正向少样本(Few-Shot)规范                  |
|    - 注入严格的输出契约指令（强制思考包裹或绝对静默）                     |
+--------------------------------------------------------------------------+
                                     │
                                     ▼
+--------------------------------------------------------------------------+
| 2. 模型采样参数层 (生成控制)                                               |
|    - 引入 presence_penalty 与 frequency_penalty 参数抑制复读               |
|    - 合理控制 max_tokens 与 temperature                                    |
+--------------------------------------------------------------------------+
                                     │
                                     ▼
+--------------------------------------------------------------------------+
| 3. 流式与静态回复过滤层 (拦截与净化 - reply_filter.py)                    |
|    - 模式A: 思考与推理前缀启发式剔除（CoT / Reasoning Prefix Filter）       |
|    - 模式B: 自省/检查模式正则匹配与丢弃                                    |
|    - 模式C: 截断与防漏兜底机制                                             |
+--------------------------------------------------------------------------+
                                     │
                                     ▼
+--------------------------------------------------------------------------+
| 4. 分段缓冲与发送门控层 (分发)                                             |
|    - 抑制纯检查/无实质回复的前置片段                                      |
+--------------------------------------------------------------------------+
```

## 3. 具体实施方案

### 方案一：过滤层升级（`mohobot/utils/reply_filter.py` 扩展）
在现有的 `ReplyArtifactFilter` 标签剥除机制后，增加非标签式自省前缀的模式剔除：

1. **识别典型自审前缀模式**：
   ```python
   # 匹配自省思考块、系统检查块、字数校验块
   REASONING_LEAK_PATTERNS = [
       re.compile(r"^(?:检查系统约束|系统约束检查|检查约束|约束检查|思考过程|分析思路)[：:].*?(?=\n\n|\n[^\s\-])", re.DOTALL),
       re.compile(r"^(?:编写回复|生成回复|拟定回复)[：:]\s*", re.MULTILINE),
       re.compile(r"(?:\n|^)(?:字数检查|字数统计|格式检查)[：:].*?(?=\n\n|$)", re.DOTALL),
       re.compile(r"符合要求[。！!.]?\s*$", re.MULTILINE),
   ]
   ```
2. **两阶段过滤设计**：
   - 第一阶段：标签与语法块剥除（`strip_reply_artifacts` 原有能力）。
   - 第二阶段：正文模式审计（若命中自省与自查前缀，提取正文部分或剔除思考说明）。
   - 提取规则：若文本包含 `编写回复：\n<真实正文>`，则截取提取实际正文，抛弃前序自查内容。

### 方案二：人设与 Prompt 模板加固
修改人设与系统提示词编写规范：
1. **禁止在 System Prompt 中使用带有自查意味的词汇**（如“在给出答案前先检查字数”）。
2. 改用不可协商的硬性契约描述：
   ```text
   【核心交流规则】
   - 直接以第一人称口语回复，严禁输出任何分析过程、规则检查、字数统计或中间草稿。
   - 输出第一句话即为最终回复。
   ```

### 方案三：参数调优（`LLMConfig` 扩展）
在 `mohobot/models/config.py` 中为 `LLMConfig` 增加采样惩罚参数：
- `frequency_penalty`: 默认 `0.2` ~ `0.4`，有效抑制单字与短语循环复读。
- `presence_penalty`: 默认 `0.1` ~ `0.3`，鼓励引入新话题词，降低模板化套话复现概率。

## 4. 实施计划与里程碑

1. **Phase 1（低风险规则与测试）**：
   - 在 `tests/test_reply_filter.py` 中补充针对 Issue #57 真实样本的回归用例；
   - 在 `reply_filter.py` 中加入无标签自省块的清洗逻辑（默认提供开关或严格匹配测试）。
2. **Phase 2（参数支持）**：
   - 在 `LLMConfig` 中暴露 `frequency_penalty` 和 `presence_penalty`，并在调用 OpenAI SDK 时传入。
3. **Phase 3（Prompt 指南更新）**：
   - 在文档和人设管理模板中加入防 OOC 最佳实践指南。
