## Project: Mohobot (Multi-Bot AI Framework)

### 1. 项目概述
构建一个基于 Python 的异步多机器人框架，接入 OneBot v11 标准。（你可以参考文件夹下的onebot-11-doc）
- 模式：反向 WebSocket (Reverse WebSocket) 服务端。
- 特性：多 Bot 接入、LLM 驱动、本地文件存储（无数据库）。

### 2. 技术栈
- 语言：Python 3.10+
- 核心：asyncio, websockets, FastAPI (仅用于后台面板 API)
- 存储：JSON / JSONL (不使用 SQL 等数据库)
- LLM：OpenAI SDK (兼容适配层)
- 日志：loguru (轮换)

### 3. 核心存储架构 (重点修改)

**原则：原始数据不可变，工作数据可变。**

#### 3.1 目录结构约定
./data/
├── bots/                  # Bot 实例配置与状态
│   └── {bot_id}/
│       ├── config.json    # Bot 独立配置
│       └── state.json     # Bot 运行状态 (如 cookies, 登录态等)
├── history/               # 【只读归档】原始聊天记录 (永不修改)
│   └── {bot_id}/
│       ├── private/
│       │   └── {user_id}.jsonl  # 私聊原始流水
│       └── group/
│           └── {group_id}.jsonl # 群聊原始流水
├── contexts/              # 【可读写】会话上下文 (AI 的工作记忆)
│   └── {bot_id}/
│       ├── private/
│       │   └── {user_id}/
│       │       ├── session_index.json  # 该用户的会话列表索引
│       │       ├── sess_001.json       # 会话1的上下文
│       │       └── sess_002.json       # 会话2的上下文
│       └── group/
│           └── {group_id}/
│               └── main.json           # 群聊默认会话上下文
└── cache/                 # 临时缓存
    └── images/            # 图片缓存 (LRU, 300MB上限)

#### 3.2 聊天历史 (History) vs 会话上下文 (Context)
- **聊天历史 (History)**:
  - **性质**: 只读归档。记录每一次收到的原始消息上报。
  - **存储格式**: JSONL (每行一个事件)。
  - **隔离**: 按 Bot ID 隔离。私聊按 User ID 分文件，群聊按 Group ID 分文件。
  - **用途**: 审计、全量回溯、训练数据导出。**绝不**用于 LLM 的实时推理输入。

- **会话上下文 (Context)**:
  - **性质**: 可读写的工作区。是 LLM 实际看到的“记忆”。
  - **存储格式**: JSON (数组结构)。
  - **多会话机制**: 
    - **私聊**: 一个 User 可以有 N 个 Session (如 `sess_001`, `sess_002`)。由 `session_index.json` 维护当前激活的 Session ID。
    - **群聊**: 默认只有一个 `main.json` 会话 (除非特殊需求)。
  - **操作**: 支持切换、删除、修改会话内容。
  - **裁剪**: 每个 Context 文件仅保留最近 30 轮对话。支持 `/forget n` 删除末尾 N 条。

#### 3.3 图片与多媒体
- 图片下载至 `cache/images/`，命名规则为 `{md5_hash}.{ext}`。
- 图片识别 (Vision): 使用 `phash` 计算特征值。
  - 若汉明距离 < 5，直接复用缓存中的 OCR/描述文本。
  - 若未命中，调用 Vision 模型，并将结果存入缓存映射表 (`cache/image_cache_map.json`)。

### 4. LLM 处理逻辑
- **模型配置**:
  - Chat Model: DeepSeek-V4-Flash (可配置)
  - Vision Model: Qwen3.5-122B-A10B (可配置)
- **Prompt 组装顺序**:
  1. System Prompt (人设)
  2. Tools Definition (工具 Schema)
  3. User Profile (昵称, QQ)
  4. Session Context (从 `contexts/` 加载的当前激活会话)
  5. Current Time & Input Message
- **消息预处理**:
  - 合并转发: 展开为纯文本，仅取首张图。
  - 视频/语音: 忽略或标记为 `[不支持的媒体类型]`。

### 5. 消息流与拦截机制
1. **接收**: OneBot v11 WebSocket 上报。
2. **归档**: 立即写入 `history/` (JSONL)。
3. **分类**: 
   - Meta/Notice (加群、戳一戳) -> 触发插件钩子，结束。
   - Message (聊天) -> 进入处理链。
4. **拦截器 (优先级从高到低)**:
   - 指令拦截 (`/` 开头) -> Command Handler。
   - 关键词拦截 (配置列表) -> 预设回复，阻断。
5. **上下文加载**: 根据 `user_id` 和当前 `session_id` 加载对应的 Context 文件。
6. **LLM 推理**: 构建 Prompt，调用 API，处理 Tool Calls。
7. **回写**: 将用户消息和 AI 回复追加到 Context 文件中。

### 6. 会话管理指令 (CLI/聊天内)
- `/sess list`: 列出当前用户的所有会话。
- `/sess new <name>`: 创建新会话并切换。
- `/sess switch <id>`: 切换会话。
- `/sess del <id>`: 删除指定会话文件。
- `/forget <n>`: 删除当前会话最近 n 条记录。
- `/hist`: 打印当前会话内容 (用于调试)。

### 7. 配置系统
- 全局: `./config/global.yaml` (端口, LLM Keys, Admin Pwd，以及其他设置)。
- Bot 独立: `./data/bots/{bot_id}/config.json` (QQ号, 昵称, 人设, 连接端点)。

### 8. Web 管理面板
- 技术: FastAPI + Server-Sent Events (SSE)。
- 认证: 密码登录 (BCrypt 哈希)。
- 功能:
  - 实时日志流。
  - **文件系统浏览器**: 允许查看 `history` 和 `contexts` 下的 JSON/JSONL 文件。
  - 在线编辑配置文件并触发 Bot 重启。
  - 统计数据展示 (消息计数、Token 消耗估算)。

### 9. 代码输出要求
- 必须使用 `async/await`。
- 文件 IO 需使用 `aiofiles` 以保证异步非阻塞。
- JSONL 写入需处理并发锁 (asyncio.Lock)。
- 代码结构清晰，模块解耦 (ws_server, llm_service, context_manager, file_store)。
